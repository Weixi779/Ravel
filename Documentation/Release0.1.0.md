# Ravel 0.1.0 用户能完成什么

状态：0.1.0 产品范围与验收基准。底层写操作串行队列、预处理、目标校验与阶段化结果契约以 [RepositoryArchitecture.md](RepositoryArchitecture.md) 为准。

## 1. 目标定位

Ravel 0.1.0 面向**已经在用 `jj` 的 Mac 用户**：

> 打开自己的仓库，看懂手上的改动，在图上把它整理成一组准备交付的 changes，摆好本地 bookmark，做错了也能恢复。即使发完这版后开发精力转回其他项目，它依然是一个每天有理由打开的工具。

- **0.1.0 硬承诺**：完整的本地浏览、整理、冲突入口与恢复闭环（第 4 节）。
- **0.1.0 候选项**：远端 `Fetch / Push`（第 5 节）。`Describe…` 第一次端到端成功后，就用 Finder 启动的 Release 构建做探针；已有凭据能推送、需交互时能退出、远端拒绝和结果未知能分清，再把 `R1`–`R3` 纳入首版，最终签名公证下载包放在 `A4` 复验。

## 2. 贯穿全篇的发版验收场景

发版前必须在一个真实仓库上完整走通以下流程（不借助终端完成本地整理闭环）：

1. 在编辑器中修改同一文件的两处独立逻辑并保存。
2. 分两次验证工作副本快照。第一次保存后切回 Ravel，窗口获焦自动快照，确认 Diff 显示两处最新改动。第二次让 Ravel 在分屏中保持可见，在编辑器继续修改并保存；Ravel 未获焦时提示磁盘有未快照修改，保留上次快照的 Diff。执行显式「更新工作副本快照」，确认两段 Diff 更新为最新内容。
3. 在 Ravel 内按现成 hunk 把这同一文件的两处改动拆成两笔 change（若勾选期间文件再次变化，提示重新查看最新 Diff）。
4. 分别为这两笔 change 写好标题与正文描述（并验证回头修改旧 change）。
5. 把其中一笔 change（或连同其后代）rebase 到另一条线上，创建或移动本地 bookmark 指向目标栈顶。
6. 故意做错一步，在操作历史/撤销入口中看清实际目标并撤销。
7. 触发一次 rebase 冲突：图上保留结果并标出受影响文件，进入外部解冲突流程，解决后回到 Ravel 确认冲突已消除。
8. 核对磁盘文件内容、历史图拓扑、`@` 位置与 bookmark 均符合预期。

若远端候选项探针通过并纳入 0.1.0，追加验收：

9. 从 Finder 启动签名公证后的发布包，选中本地 bookmark，预览目标 remote、远端 bookmark 的起止位置、将公开的提交与将被移出的提交，完成首次发布。
10. 模拟远端前进导致 Push 被拒，按提示 Fetch 后重新查看差异（整合对方提交、处理 bookmark 冲突或明确确认移动指针），再决定如何发布；模拟回包前断线，确认界面进入「推送结果待确认」并支持 Fetch 核对。

## 3. 跨功能交互约定

- **右键点谁，就操作谁**：首版用上下文菜单把对象操作做透，不以图上拖拽为前提。
  - 历史行：操作该 revision（`Describe…`、`New on This Change`、`Edit This Change`、`Split…`、`Squash into…`、`Rebase…`、bookmark 操作、复制 ID）。
  - 文件行：操作该文件改动（移动文件改动到另一笔 change、在 Finder 中显示、打开文件、复制路径）。
  - Bookmark：操作该书签（移动书签、删除书签；若纳入远端，则包含推送该书签）。
- **严格区分三类动作命名**：改变父子关系叫 **Rebase**，改变两笔提交的内容归属叫 **Split / Squash / Move Changes to…**，改变书签指向叫 **Move Bookmark…**；不统称为 `Move…`。
- **选目标时来源始终可见，执行前能念成一句人话**：跨节点操作在挑选目标期间保持来源常驻可见，目标不在当前图视口内也能查找；执行前展示清晰摘要（例如「将 `kmpv` 和它的 2 笔后代移到 `main` 上」），执行前可随时取消。
- **做完能解释发生了什么**：清晰区分正常成功、部分成功、前置拦截、确定失败与结果待确认，避免用户在不确定状态下盲目重试。

## 4. 0.1.0 硬承诺：用户能完成的五件事

### 4.1 从当前工作出发，也能回头改旧的一笔

- **定位与查找**：
  - `⌘0` 能可靠定位到 `@`——**即使历史分页尚未加载到 `@` 所在页也能找到并选中**。
  - 支持按描述、Change ID、Bookmark 快速查找目标 revision（同时复用为 Rebase / Squash 目标查找）。
  - 侧边栏提供 `@` 与 Bookmarks 快捷跳转入口。
  - 历史图在执行操作前即清晰呈现判断依据：`immutable`、冲突、空提交（`empty`）、本地/未同步/远端/冲突 bookmark，以及 Change ID 的最短唯一前缀。
- **基础变更操作**：
  - **`Describe…`**（首个做透的写操作）：支持在 `@` 或任意旧的可变 change 上编辑标题与多行正文；保存后继续选中该 change；取消保留原文；对 `immutable` 节点明确说明不可改写原因。
  - **`New on This Change`**：在目标 change 上新建子 change，图刷新并选中新创建的 change。
  - **`Edit This Change`**：将工作区切换到目标可变 change；对 `immutable` 节点给出明确原因。

### 4.2 把混在一起的工作整理开

- **`Split`（支持文件级 + 按现成 hunk 拆分）**：
  - 支持勾选整份文件把一笔 change 拆成两笔。
  - 支持在同一文本文件内**按现成 hunk 勾选拆分**（解决同一文件混入多项改动无法拆开的真实痛点）；逐行编辑补丁不在 0.1.0 范围。
  - 对 `@` 拆分前，若磁盘存在尚未快照的改动，先通过显式的「更新工作副本快照」加载最新 Diff 后再勾选 hunk；若勾选完成后提交前文件或目标再次变化，阻止静默执行并提示用户重新查看最新 Diff。
  - 二进制文件、仅权限/重命名改动、冲突文件按文件级处理并清晰标识。
- **`Squash` 与移动文件改动**：
  - 支持将整笔 change 或指定文件改动移入父提交或其他可变 change。
  - 源与目标存在不可改写约束时提前拦截并说明原因。

### 4.3 在图上移动工作与管理本地书签

- **`Rebase`**：
  - 支持两种范围：**「只移这笔」**与**「连同后代移到目标上」**。
  - 选择目标期间来源始终可见，支持查找未在当前视口内的目标，执行前念出明确人话摘要。
  - 完成后图刷新，选择跟随被移动的 change。
- **本地 `Bookmark`**：
  - 支持在指定 revision 上创建本地 bookmark、将已有本地 bookmark 移动到另一 revision、删除本地 bookmark。
  - 完成后历史图与侧边栏同步更新。

### 4.4 与编辑器、终端一起工作

- **按窗口可见性感知变化，不做后台无脑刷新**：
  - **窗口可见时**（含与终端/编辑器分屏或副屏显示，对应 macOS 窗口可见态 `occlusionState.contains(.visible)`）：
    - 仓库产生新 `jj` operation 时自动轻量核对 `op_heads` 并无闪烁刷新；仓库未变化时不重复全量重载。
    - 编辑器保存磁盘文件但尚未 snapshot 时，界面立即呈现“磁盘有未快照修改”的状态，并提供显式「更新工作副本快照」入口。
  - **窗口获得焦点时**：自动执行一次工作副本快照（走写队列，无实际改动则零噪音），不额外增加配置开关，让“编辑器保存 → 切回 Ravel 看新 Diff”默认即顺手。
  - **统一跳过条件**：处于 Split 勾选模式或写队列正忙时，直接跳过上述自动刷新与自动快照，避免冲掉勾选进度或争抢工作区锁；Split 提交前仍做目标校验兜底。
  - **窗口不可见时**（最小化、隐藏或被完全遮挡）：不刷新、不自动快照，仅记录待核对标记；等用户再次切回或恢复显示时统一检查更新。
- **写前校验与部分成功反馈**：
  - 写操作在预处理之后按完整 commit/change 身份校验目标；若终端在准备期间改写了目标，提示用户重新查看最新状态，绝不静默重定向。
  - 面对「操作已提交，但工作区更新或 Git 导出失败」这类部分成功，明确说明已完成的部分与失败环节，防止用户点重试重复执行。
  - 关闭界面或切换视图不会静默丢弃进行中的写操作回执。

### 4.5 做错有退路，发生冲突有下一步

- **操作历史与 `Undo`**：
  - 用户能看到近期操作并撤销；若期间终端也做过新操作，撤销入口必须明确指出**实际会撤掉哪一步**，而不是模糊地执行“撤销”。
  - 撤销文案明确作用于本地操作历史。
  - 遇到工作区过期（stale working copy）或并发 operation head 时，提供清晰的说明与恢复入口。
- **冲突处理闭环**：
  - Rebase / Squash 产生冲突时，图上保留结果并明确标出冲突 revision 与受影响文件。
  - 提供「使用外部工具解冲突」或「撤销本次操作」的直接下一步。
  - 从外部解冲突工具返回后，Ravel 能刷新并确认冲突是否已经全部解决。

## 5. 0.1.0 候选项：远端 `Fetch / Push`（带实测门禁）

### 5.1 早期验证门禁（`R0`）

**触发时机与通过标准**：`Describe…` 第一次端到端成功后，就用 Finder 启动的 Release 构建做探针。已有凭据能推送、需交互时能退出、远端拒绝和结果未知能分清，再把 `R1`–`R3` 纳入首版。最终签名公证下载包放在 `A4` 复验。

探针实测清单（一次性测试仓库）：

- 核验本机环境满足 `jj-lib 0.41.0` 要求的 **Git ≥ 2.41.0**，缺失或版本不足时给出明确提示。
- 实测三条认证路径：
  1. 已有可用 SSH agent → 直接走通。
  2. 已有可用 HTTPS Keychain 凭据 → 直接走通。
  3. 需要额外交互（SSH passphrase、首次主机确认、缺少凭据等）→ 及时结束不挂死，解释原因，并直接给出针对当前 remote 和 bookmark 的终端命令。
- 实测首次发布、远端前进拒绝、取消时的子进程行为与回包断线。

### 5.2 纳入 0.1.0 时的验收边界

- **`Fetch`**：从明确的 remote 拉取更新，完成后历史图与 bookmark 反映远端最新状态。
- **`Push`**：
  - 支持首次发布新建本地 bookmark，也支持再次更新已有 bookmark。
  - **执行前预览必须清晰回答“这次到底会公开和改变什么”**：展示目标 remote、该远端 bookmark **将从哪里移到哪里**、本次将带出去的新提交集合（含依赖的祖先提交），以及**哪些提交会从这条远端线上被移出**（覆盖首次带出祖先栈与改写已发布历史两种场景）；并在上层对齐 `git.private-commits`、空描述、冲突等检查（不依赖 `jj-lib::git::push_refs()` 自行校验）。
  - 远端已前进导致拒绝时，清楚解释原因并引导先 Fetch；Fetch 完成后由用户重新查看差异（整合提交、处理 bookmark 冲突或明确确认移动指针），再决定如何发布。
- **远端恢复语义**：
  - 明确区分**确定失败**、**远端结果待确认**（如回包前断线，允许用户 Fetch 核对，不显示“已取消”，也不自动重试）与**远端已成功但本地状态尚未同步**。
  - `Undo` 明确不撤回已推送到远端的内容。

## 6. 下载、安装与授权验收

- **授权合规**：最终分发包与公开源码仓在第三方依赖（特别是 `STTextView 2.4.1` 的 GPLv3 / 商业授权）上保持合法且无歧义。
- **干净环境启动**：使用 Developer ID 签名并完成 Apple 公证；在干净的 Mac 环境下从下载包直接启动，可打开本地 `jj` 仓库并跑通主流程。
- **文档与实际一致**：`README.md` 写清支持的 macOS 版本、仓库前提（含远端若纳入时的 Git 版本条件）、第一条完整工作流与已知限制。

## 7. 0.1.0 明确的非目标

以下能力排在 0.1.0 之后，不作为首版发版条件：

- 图上拖拽操作（拖节点 rebase、拖文件移改动、拖书签）
- 逐行手工编辑补丁拆分、内置三栏可编辑冲突合并器
- 完整的账号系统与 `GIT_ASKPASS` / `SSH_ASKPASS` 凭据弹窗
- 完整 Revset 语法编辑器、多窗口/多标签（`WindowGroup`）、Tree-sitter 完整语法高亮
- 非阻塞性的界面像素级精修（顶栏具体高度微调、Diff 卡片边框等）与存量视图全量 `#Preview` 补齐
